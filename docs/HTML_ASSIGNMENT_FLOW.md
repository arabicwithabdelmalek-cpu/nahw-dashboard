# رحلة إسناد ملفات HTML للفصول والطلاب — نموذج متكامل تجريبي

> التاريخ: 10 نوفمبر 2026. **الحالة: واجهة تجريبية عاملة ببيانات مؤقتة، وليست تكليفات رسمية محفوظة في Supabase.**

## ما يعمل الآن

يمكن للمدير أو المعلم الدخول إلى وضع المعاينة `?demo=1`، ثم اختيار **الدروس ← افتح الربط التجريبي بالفصول والطلاب**.

1. اختيار فصل من الفصول التي يراها المعلم في بيانات المعاينة.
2. اختيار نوع المحتوى: **درس** أو **واجب** أو **اختبار**.
3. إسناد نموذج نحوي جاهز، أو تحديد ملف HTML مستقل من الجهاز (أقل من ٢ ميجابايت). يُقرأ الملف في ذاكرة المتصفح فقط ولا يُرفع إلى الخادم.
4. ظهور التكليف في صفحة `#/activity-demo` للطالب المرتبط بالفصل التجريبي.
   - في وضع المعاينة فقط، يمكن الضغط على **«تجربة واجهة الطالب»** من صفحة المعلم، ثم **«العودة لواجهة المعلم»** بعد التسليم؛ لا تحتاج إلى تسجيل خروج ولا يؤثر التبديل على بيانات Supabase.
5. فتح الملف من خلال عارض `EduActivityPreview` المعزول `sandbox="allow-scripts"`، مع عقد `EDU_PLATFORM_INIT` و`EDU_ACTIVITY_COMPLETED` و`EDU_ACTIVITY_RESULT`.
6. ظهور حالة الطالب وآخر نتيجة تجريبية في صفحة المعلم عند الرجوع للدور نفسه داخل الصفحة (من دون إعادة تحميل).

التكليفات والمحاولات تحفظ في **مصفوفات JavaScript داخل جلسة الصفحة فقط**. تسجيل الخروج ثم الدخول بدور مختلف في الصفحة نفسها يبقي بيانات المحاكاة مؤقتًا؛ تحديث الصفحة أو إغلاقها يفقدها. **لا يوجد اتصال كتابة إلى Supabase أو LocalStorage.**

### قيود فعالة

- يعمل المسار التجريبي فقط عندما يتضمن الرابط `?demo=1`. وحدة التكليفات ترجع دون تسجيل مستمعي الأحداث في الإنتاج العادي.
- المدير أو المعلم لا يسند إلا لفصل من القائمة المحمَّلة له، والطالب لا يرى إلا تكليفات فصل حسابه التجريبي.
- لا يتم استخدام `supabase.from()`، أو `supabase.rpc()`، أو `auth` لإسناد النشاط أو استقبال النتيجة في المحاكاة.
- لا تتغير واجبات `lesson_files` القديمة، ولا دالة `submit_result`، ولا عرض النتائج التاريخية.
- وجود نتيجة داخل ذاكرة المتصفح **لا يثبت صحتها أو هوية مرسلها**؛ هو مثال لتجربة المستخدم فقط.

## التحقق المنفذ

اجتاز النموذج **23 حالة اختبار برمجي** تشمل:

- فحص JavaScript لكل ملفات الوحدات في سلسلة التحميل.
- عرض صفحة الدخول للمعاينة، وصفحة إسناد النشاط للمعلم.
- تحديد فصل حقيقي من بيانات `NAHW_DEMO`، ونوع «واجب»، وإنشاء تكليف تجريبي.
- ظهور تكليف الطالب داخل `#/activity-demo` بعد تغيير الدور داخل الصفحة.
- فتح الملف في إطار ذي `sandbox="allow-scripts"`.
- استقبال `EDU_PLATFORM_INIT` بمعرّفين فريدين مؤقتين.
- رفض رسالة نتيجة ذات معرّف محاولة غير مطابق.
- قبول النتيجة الصحيحة `2 / 2` وإظهارها للطالب.
- تجاهل النتيجة المكررة.
- عرض `1 / 2` سلّموا، مع آخر درجة للطالب، بعد العودة إلى دور المعلم.
- اختبار إضافي من **8 خطوات ناجحة** للتحويل بين المعلم والطالب والعودة، مع بقاء التكليف والنتيجة في الذاكرة.
- طلب الشبكة الوحيد خلال رحلة الاختبار هو جلب ملف النموذج الثابت من `examples/html-activity-example.html`.

**حدود الاختبار:** استخدمت المحاكاة بيانات مُختلقة وDOM وهميًا. ليس هذا إثباتًا لعمل كل الوظائف في متصفح حقيقي أو للحماية الخادمية. ينبغي تنفيذ اختبار متصفح مستقل بعد النشر.

## التصميم الخلفي المستقبلي — مقترح لا يُطبّق بعد

أسماء الكيانات أدناه **افتراضات تصميم تحتاج مراجعة المخطط الحقيقي** قبل إنشاء migration:

| الكيان المقترح | دوره |
|---|---|
| `activity_files` | ملف HTML خاص بإصدار وبصمة، وتخزين في Storage خاص أو جدول مناسب بعد التدقيق |
| `activity_assignments` | إسناد إصدار نشاط إلى فصل، مع النوع والموعد والمعلم |
| `activity_attempts` | محاولة طالب في تكليف معين، وحالتها ووقت الإرسال والدرجة الاختيارية |
| `activity_events` (اختياري) | سجل الأحداث المحققة خادميًا ومنع التكرار وتتبّع محاولات التسليم |

### ما يجب أن تتحقق منه قاعدة البيانات

1. لا يحصل الطالب على ملف HTML إلا إذا كان مُصادَقًا ومربوطًا بفصل يملك تكليفًا فعّالًا.
2. لا يسند المعلم ملفًا إلا إلى فصل مخوَّل بإدارته، والمدير يُقيّد وفق صلاحيات المشروع الفعلية.
3. لا يُقبل `student_id` أو `class_id` المرسل من JavaScript بوصفه حقيقة؛ الخادم يستخرج هوية المستخدم وفصله من سجلات موثوقة.
4. يصدر الخادم معرّف المحاولة، ويتحقق من صلته بالتكليف والطالب وتاريخ الصلاحية.
5. يمنع التكرار بقاعدة `UNIQUE` أو مفتاح idempotency، ويقبل `completed` دون درجة.
6. تكون `score` و`max_score` إما كلتاهما صالحتين أو كلتاهما `NULL`، ويكون نطاق الدرجة محفوظًا.
7. لا تُستخرج درجة من مجرد فتح الملف أو إغلاقه.
8. ينبغي تمييز درجات HTML التي حسبها المتصفح عن التقييمات ذات التحقق الخادمي، لأن العميل يستطيع تزوير النتائج.
9. لا نُعدّل سجلات `submissions` القديمة ولا نغيّر معرّفات الطلاب الموجودة.
10. يتم تقييم سياسة `RLS` و`GRANT` و`EXECUTE` ودوال `SECURITY DEFINER` قبل استخدام هذه الكيانات.

3. اختيار نوع «واجب» وإسناد النموذج إلى «فصل تجريبي».

6. ظهور النشاط للطالب وبدء تشغيله.
7. الإجابة الصحيحة عن السؤالين.
8. ظهور نتيجة `2 / 2` في واجهة الطالب.
9. الرجوع إلى واجهة المعلم بزر خاص.
