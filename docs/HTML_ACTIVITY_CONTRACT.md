# عقد أنشطة HTML — الإصدار 1.0

> **حالة التنفيذ بتاريخ 10 نوفمبر 2026:** العقد يعمل حاليًا في **معاينة محلية تجريبية داخل صفحة «الدروس»**. الإسناد الحقيقي والحفظ في Supabase واستقبال النتائج الرسمية **غير منفَّذ**. لا يجوز اعتبار المعاينة نظام تسليم واجبات جاهزًا للإنتاج.

## 1. الهدف

تُنشأ ملفات **الدرس، والواجب، والاختبار** خارج المنصة باستخدام Claude Skills. المنصة مسؤولة مستقبلًا عن حفظ الملف وإصداره وتصنيفه وتحديد الطلاب المصرح لهم، ثم عرضه واستقبال *حدث الإتمام أو النتيجة المرسلة من HTML نفسه*. **المنصة لا تُنشئ أسئلة ولا تصحح إجابات ولا تخمّن درجة ملف صامت**.

هذا العقد مستقل عن التصميم والمحتوى، ويُسمح لأي Skill بإنتاج نشاط بتنسيق مختلف ما دام يلتزم برسائل الاتصال.

## 2. خصائص الملف

- ملف واحد فقط `.html` أو `.htm`، به HTML وCSS وJavaScript داخليان؛ ويفضل أن يكون مكتفيًا بذاته دون اعتماد على موارد الشبكة.
- اتجاه عربي `dir="rtl"` وتصميم مناسب للشاشات الصغيرة.
- لا يحتوي مفتاح Supabase أو رمز جلسة أو كلمة مرور أو بيانات طالب خاصة.
- لا يعتمد على `window.parent.document`، أو `localStorage` للمنصة، أو الوصول المباشر إلى جداول Supabase.
- لا يحتاج فتح نافذة منبثقة أو التنقل إلى الصفحة العليا.
- أقصى حجم **لأداة المعاينة الحالية** ٢ ميجابايت؛ حد الرفع الدائم لم يُحسم بعد.

## 3. أسلوب تشغيل المعاينة

من لوحة المعلم أو المدير: **الدروس ← تجربة ملفات HTML الحديثة**، ثم اختر **تجربة نموذج نحوي** أو **معاينة ملف من جهازك**.

تستخدم المعاينة إطارًا يحتوي على:

```html
<iframe sandbox="allow-scripts" referrerpolicy="no-referrer"></iframe>
```

- **لا** نضيف `allow-same-origin`؛ لذلك يحصل الملف على أصل معزول `opaque origin` ولا يستطيع قراءة بيانات الأصل الرئيسي.
- يُدرج في الملف عند المعاينة **CSP** في بداية `head`، يتيح السكربتات والتنسيقات الداخلية مؤقتًا، ويمنع الطلبات الشبكية والملفات الخارجية والنماذج والعمال والإطارات المتداخلة. هذا متعمَّد من أجل HTML المكتفي بذاته.
- لا تنفِّذ المعاينة أي RPC ولا تحفظ محاولة أو درجة أو ملفًا. لا تستخدمها باعتبارها دليلًا على نجاح تسجيل النتائج الحقيقي.
- تحقّق مصدر الرسائل يجمع بين `event.source === iframe.contentWindow` و`event.origin === "null"`، مع التحقق من نوع الحدث والإصدار والمعرّفات.
- `attemptId` و`assignmentId` في المعاينة معرّفات **مؤقتة للعرض فقط**، وليست صلاحية تسجيل درجات.

## 4. رسائل الربط

### أ. من المنصة إلى ملف HTML — بعد تحميل الإطار

```json
{
  "type": "EDU_PLATFORM_INIT",
  "version": "1.0",
  "attemptId": "preview-attempt-generated-at-runtime",
  "assignmentId": "preview-assignment-generated-at-runtime",
  "context": { "displayName": "متعلم تجريبي" }
}
```

رسالة التهيئة لا تحتوي رموز وصول أو بيانات حساسة. لا يُرسل ملف HTML إكمالًا أو نتيجة قبل استقبال هذه الرسالة.

### ب. إتمام النشاط بلا درجة

```json
{
  "type": "EDU_ACTIVITY_COMPLETED",
  "version": "1.0",
  "attemptId": "same-runtime-attempt-id",
  "assignmentId": "same-runtime-assignment-id",
  "completedAt": "2026-11-10T10:00:00Z"
}
```

تعني أن **الملف أعلن إتمام النشاط**، لا أن الطالب حضر حصة، ولا تعني حصوله على درجة.

### ج. النتيجة التي يحسبها الملف بنفسه

```json
{
  "type": "EDU_ACTIVITY_RESULT",
  "version": "1.0",
  "attemptId": "same-runtime-attempt-id",
  "assignmentId": "same-runtime-assignment-id",
  "score": 2,
  "maxScore": 2,
  "completedAt": "2026-11-10T10:00:00Z"
}
```

الملف نفسه يصحح أسئلته إن كانت قابلة للتصحيح، ثم يرسل `score` و`maxScore`؛ المنصة لا تحسب تصحيح الأسئلة.

### د. إرسال الرسالة داخل ملف HTML

```javascript
window.parent.postMessage({
  type: "EDU_ACTIVITY_COMPLETED",
  version: "1.0",
  attemptId: currentAttemptId,
  assignmentId: currentAssignmentId,
  completedAt: new Date().toISOString()
}, "*");
```

يُستخدم `"*"` لأن إطار `sandbox` ذو أصل معزول. لذلك لا يُرسل أبدًا أي سر أو بيانات شخصية حساسة في الرسائل، ولا تُقبل الرسالة بوصفها تفويضًا لمجرد وصولها.

## 5. التحقق في المعاينة مقابل الخادم

| التحقق | المعاينة الحالية | النظام النهائي المطلوب |
|---|---|---|
| هوية الإطار ورسالة الإصدار والمعرّفات | منفّذ | مطلوب |
| مدى الدرجة | منفّذ بصريًا: `0 ≤ score ≤ maxScore ≤ 1000` | يجب تعريفه بحسب النشاط |
| منع تكرار عرض حدث من النوع نفسه | منفّذ داخل جلسة المعاينة | قيد `idempotency` في الخادم |
| تطابق المستخدم مع محاولة الطالب | **غير منفّذ** | تحقق عبر Supabase Auth/RLS/RPC |
| صلاحية الطالب لدخول الفصل والنشاط | **غير منفّذ** | مطلوب قبل إتاحة الملف وقبول النتيجة |
| حفظ النتيجة في قاعدة البيانات | **غير منفّذ** | عملية خادمية تتحقق ثم تحفظ |
| الحضور والدرجات التاريخية | لا يمسها | الحفاظ عليها وعدم الخلط بينها وبين الإتمام |

**تحذير:** لا تُعتبر درجة أرسلها JavaScript من متصفح الطالب محصنة ضد التلاعب؛ قد تتطلب الاختبارات عالية الحساسية آلية تحقق إضافية، دون إنشاء محرك تصحيح داخل المنصة.

## 6. التوافق مع واجبات النحو القديمة

- المسار الحالي `#/lessons` لرفع الواجبات القديمة، و`parseHomework`، و`lesson_files`، و`submit_result`، وبوابة الطالب **بقيت كما كانت**.
- المعاينة الجديدة مستقلة؛ اختيار ملف فيها **لا يرفعه إلى قاعدة البيانات**.
- ما زال عارض الواجبات القديمة يعتمد `iframe.srcdoc` من دون `sandbox`. هذه **مخاطرة أمنية قائمة**؛ لم نغيّر هذا المسار قبل الاطلاع على ملفات الإنتاج القديمة واختبار توافقها.
- عند الترحيل لاحقًا نحتاج فصل نوع الملف الجديد عن ملفات النحو القديمة، وإبقاء القديمة قابلة للعرض واسترجاع المحاولات، وتحقيق عزل تدريجي مع مسار توافق.

## 7. تجربة المثال

ملف جاهز: [`examples/html-activity-example.html`](../examples/html-activity-example.html).

يجرب خيارين: **إكمال من غير درجة**، أو **الإجابة عن سؤالين وحساب نتيجة داخل الملف**. يظهر إشعار في أعلى المعاينة بالحدث المستلم؛ **لا تسجل النتيجة في `submissions`**.

## 8. المتطلبات اللازمة قبل إطلاق التسليم الرسمي

1. فحص جداول Supabase الفعلية وسياسات RLS/DAL ودوال `my_homework` و`submit_result` أولًا، وحفظ نسخة احتياطية قابلة للاستعادة.
2. تعريف تكليفات وإصدارات وأنشطة مرتبطة بالمواد والحصص دون كسر IDs القديمة.
3. تخزين HTML بخاصية الخصوصية وبدون إتاحة عامة عشوائية؛ اختبار `Storage` أو آلية `lesson_files` الحالية.
4. إصدار المحاولة من الخادم وتثبيت مالكها ووقت بدئها وانتهائها.
5. التحقق الخادمي من نوع الحدث ومدى الدرجة والطالب والفصل والتكليف والصلاحية والتكرار.
6. إظهار حالة **لم تُرسل نتيجة** عندما لا يرسل HTML شيئًا، وعدم افتراض درجة أو إتمام لمجرد فتحه.
7. تدقيق كل المسارات الحساسة واختبار HTML قديم، جديد، خارجي، ملتبس، مكرر، ومحاولة طالب غير مصرح له.

**مراجع تقنية:** [MDN iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox) و[MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy).

## 9. ما يُطلب لاحقًا من Claude Skills

تُنشئ مهارة Claude ملف HTML واحدًا مستقلاً ومتجاوبًا، مع استقبال `EDU_PLATFORM_INIT`، وإرسال `EDU_ACTIVITY_COMPLETED` أو `EDU_ACTIVITY_RESULT` **عند إتمام المتعلم بالفعل**، دون أي مفاتيح أو اتصال مباشر بقاعدة البيانات. تُراجع صيغة العقد الفعلية هنا قبل إصدار ملفات جديدة.
