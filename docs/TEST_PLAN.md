## 8. منهج تنفيذ الاختبارات مستقبلًا

1. **عزل البيئة:** نسخة اختبار ببيانات اختبار/نسخة مُخفاة الهوية وفق ضوابط الخصوصية، بدون كتابة اختبارات على الإنتاج.
2. **مصفوفة المستخدمين:** مدير رئيسي، معلّمان مختلفان، طالبان في فصلين، طالب مؤرشف/غير مفعل، وزائر مجهول.
3. **استيثاق الخادم:** لكل إجراء حساس، اختبار REST/RPC مباشر بجلسات الأدوار المختلفة وليس واجهة المستخدم فقط.
4. **توثيق قبل/بعد:** حفظ عدادات السجلات وأسماء السياسات وأرقام migration والـcommit المجرَّب دون حفظ كلمات مرور أو بيانات شخصية.
5. **حالات الخطأ:** فقد الإنترنت، جلسة منتهية، HTML قديم، ملف مرفوض، إرسال نتيجة مكرر، انتقال بين الصفحات.
6. **الهاتف:** اختبار RTL والتمرير ولوحة المفاتيح والحجم وiframe وإغلاق النوافذ.
7. **بوابة الإطلاق:** أي فشل AUTH أو HTML-03/04 أو BACKUP-01 يمنع تشغيل مكوناته الجديدة على الإنتاج.

## 9. طريقة تسجيل النتيجة لكل اختبار

- اسم الاختبار ورمزه، التاريخ، الفرع/commit، البيئة.
- حساب الاختبار وصلاحياته بصورة غير حساسة.
- الخطوات والنتيجة المتوقعة/الفعلية.
- نتيجة من: `PASS` أو `FAIL` أو `BLOCKED` أو `NOT RUN`.
- سجل أخطاء منقح من الأسرار ومراجع screenshots/console عند الحاجة.

## 10. الخلاصة المرحلية

**المرحلة 0 من جهة الكود أُنجز فيها:** جرد المسارات والخدمات، قراءة static، اختبار Syntax، اختبار الوصول لشاشة الدخول، snapshot Git، وخطة اختبار مفصلة.

**غير المنجز بسبب الاتصال:** فحص القاعدة والصلاحيات، نسخة DB وStorage قابلة للاستعادة، الاختبارات الحقيقية للأدوار والواجبات. لا توجد موافقة بنشر تغييرات جديدة على `main`.
