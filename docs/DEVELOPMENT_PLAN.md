# خطة تطوير منصة النحو الواضح

> وثيقة عمل مشتركة للمشروع؛ أُعدّت اعتمادًا على الكود الموجود في GitHub، دون الوصول إلى قاعدة بيانات Supabase التابعة للمشروع.

## الحالة الحالية (10 نوفمبر 2026)

- المستودع: https://github.com/arabicwithabdelmalek-cpu/nahw-dashboard
- الموقع المنشور: https://arabicwithabdelmalek-cpu.github.io/nahw-dashboard/#/
- فرع الإنتاج: `main`. فرع العمل: `development`.
- ملفات المشروع الحالية: `index.html` و`README.md` و`.nojekyll`.
- الواجهة مكتوبة في ملف HTML واحد كبير يضم CSS وJavaScript، مع توجيه صفحات عبر `location.hash`.
- الواجهة منشورة عبر GitHub Pages، وتستخدم Supabase للمصادقة وتخزين البيانات.
- معرّف مشروع Supabase المضمّن في إعدادات الواجهة: `vkjkkezuyhhlcrxlvdbr`.
- حساب Supabase المتصل حاليًا لا يتيح لنا الوصول إلى هذا المشروع؛ لذلك **لا نعدّل قاعدة البيانات ولا نفترض تصميم السياسات والجداول غير المفحوصة**.

## ما تأكدنا من وجوده في الكود

- تسجيل دخول لأدوار المدير والمعلم والطالب، مع بوابة للطالب.
- أقسام الواجهة: الرئيسية والفصول ومكتبة الدروس والنتائج الواردة والمعلمون.
- إنشاء فصول، إدارة الطلاب والحسابات، وربط الدروس بالفصول.
- رفع ملفات واجبات HTML بصيغة متوقعة في التطبيق؛ تُخزّن نسخ الملفات والأسئلة في قاعدة البيانات.
- استعراض الواجبات والمحاولات والنتائج، واستقبال أكواد نتائج عبر دالة قاعدة بيانات.
- جداول يتعامل معها الكود: `profiles`, `classes`, `students`, `lessons`, `lesson_versions`, `submissions`, `class_lessons`, `lesson_files`.
- دوال قاعدة بيانات يستدعيها الكود: `setup_needed`, `attach_teacher`, `attach_student`, `submit_result`, `my_portal`, `my_homework`.

**تنبيه:** وجود الاستدعاءات في الكود لا يثبت صحة إعدادات قاعدة البيانات أو نجاحها تحت جميع الصلاحيات؛ لا يمكن الحكم على ذلك قبل اتصال Supabase الصحيح واختبارات حسابات تجريبية.

## الهدف

تحويل لوحة مرتبطة بكتاب واحد إلى **منصة تعليمية متعددة المواد والفصول** لإدارة المدير والمعلمين والطلاب والدروس والحصص والواجبات والاختبارات والنتائج، مع الحفاظ على عمل الموقع الحالي وبياناته.

### قرارات أساسية معتمدة

1. لوحة مدير واحدة، وصلاحيات منفصلة للمدير والمعلم والطالب.
2. قائمة المدير المقترحة: الرئيسية، الفصول، الطلاب، الدروس، الحسابات، ثم الوظائف الإدارية الأخرى عند الحاجة.
3. قائمة المعلم: الرئيسية، الفصول، الطلاب، الدروس؛ مع الوصول للحضور ونتائج طلابه ضمن السياق المناسب.
4. واجبات واختبارات HTML تُنشأ خارجيًا وتُرفع إلى المنصة، **ولا يُبنى محرك تصحيح تلقائي جديد داخل المنصة**.
5. تسليم نتائج الواجب تلقائيًا بعد إنجاز الطالب *عند استيفاء عقد الربط والتحقق الأمني*؛ لا نفترض أن أي ملف HTML يعمل دون تهيئة.
6. الطالب يرى حصصه وواجباته ونتائجه وترتيبه وفق نطاق واضح وخصوصية مناسبة.
7. دعم تسجيل الحضور في الحصة، ولوحة ترتيب الطلاب، وسجل دخول/نشاط بعد إنشاء البنية اللازمة والتحقق من صلاحياتها.
8. التصميم عربي RTL، بسيط، واضح، متجاوب، بخط Cairo عندما تتوافر ملفاته أو تحميله بشكل موثوق.

## حدود العمل الحالية

- يمكن تعديل كود GitHub وتنظيمه وإعداد واجهات وتوثيق وخطط SQL دون الاتصال بقاعدة البيانات الثانية.
- لا يمكن تأكيد حالة الجداول، سياسات RLS، أو تطبيق تغييرات SQL على مشروع «النحو الواضح» قبل إتاحة صلاحية الوصول.
- لا تُحذف أو تُنقل بيانات المستخدمين، ولا تُعدّل مفاتيح المشروع أو عنوان Supabase دون مراجعة.
- تُجرَّب التغييرات على `development` أولًا. وجود فرع وحده لا يعني توفر رابط معاينة منشور له.

## أول مهمة عملية تالية

**أُنجزت البداية:** صفحة `#/students` على فرع `development`، وتم فحص بناء JavaScript واختبار عرض تجريبي للأدوار والتصفية. لم يُختبر تسجيل الدخول الحقيقي بعد.

**المهمة التالية:** تحسين تنظيم قوائم المدير والمعلم (ومنها الحسابات)، ثم التمهيد لتقسيم ملف `index.html` الكبير دون المساس بالبيانات، وإجراء فحص تكامل عند توفر قاعدة البيانات.

## قواعد تسليم أي تعديل

1. قراءة آخر نسخة من فرع `development` قبل الكتابة؛ لا تكتب فوق عمل Claude أو ChatGPT الآخر.
2. تحديد الملفات المتأثرة ونطاق التغيير قبل التنفيذ.
3. إبقاء التعديل محدودًا ولا يغيّر البيانات الموجودة إلا بطلب صريح.
4. اختبار بناء/سلامة الكود، ثم فحص الصفحات المتأثرة.
5. توثيق ما اكتمل، وما لم يُختبر، وما يحتاج Supabase.
