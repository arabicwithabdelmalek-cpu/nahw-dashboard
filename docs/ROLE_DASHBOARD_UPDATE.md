# تنظيم لوحات المدير والمعلم والحسابات

> التاريخ: 10 نوفمبر 2026 — تحسين واجهات موجودة، دون SQL أو تغيير قاعدة بيانات أو نقل درجات.

## ما نفذناه

### لوحة المعلم

القائمة الأساسية الآن **أربعة أقسام فقط**: الرئيسية `#/`، الفصول `#/classes`، الطلاب `#/students`، الدروس `#/lessons`.

- صفحة «النتائج الواردة» ما زالت موجودة في `#/inbox` ويمكن الوصول إليها من زر واضح أعلى الرئيسية، ومن رابط «الكل» في آخر النتائج.
- لا تزال الصفحة تدعم لصق نتائج واتساب وربط النتائج غير المنسوبة بالطلاب ضمن الإجراءات والصلاحيات الموجودة مسبقًا.
- انتقل تمييز القائمة في صفحة الطالب التفصيلية إلى «الطلاب» بدل «الفصول».

### لوحة المدير

القائمة الرئيسية: **الرئيسية، الفصول، الطلاب، الدروس، الحسابات**.

- صفحة `#/accounts`: تجمع القائمة القديمة للمعلمين وإضافة معلم جديد، مع قسم يوضح حالة حساب الدخول لكل طالب في الفصول.
- الطلاب الذين لا يملكون `user_id` يُعرض لهم زر «إنشاء حساب» يستخدم الإجراء `studentLogin` **الموجود سابقًا**؛ لا توجد واجهة وهمية.
- الطلاب الذين لديهم حساب يظهر لهم رابط «عرض» يفتح صفحة الطالب الحالية.
- الإحصاءات تعرض عدد المعلمين، والطلاب المرتبطين بحساب دخول، والطلاب غير المرتبطين.
- رابط `#/teachers` القديم يظل صالحًا، ويفتح صفحة الحسابات الجديدة من أجل توافق الروابط السابقة.
- لا يوجد في واجهة تغيير أدوار المعلمين اختيار لترقية معلم إلى «مدير»، ولا تعرض الإدارة زر حذف أو تغيير دور حساب مدير آخر. **هذا تقييد واجهي فقط، وليس ضمانًا خادميًا لحساب مدير واحد**؛ لا بد من حماية ذلك داخل RLS/RPC.

## الحفاظ على الموجود

- شاشة دخول الطالب والمدير والمعلم لم تُعدل.
- ما زالت مسارات `#/inbox`، `#/teachers`، `#/student/...`، `#/class/...`، `#/lesson/...` متاحة.
- لم تتغير طريقة قراءة أو حفظ الطلاب أو الواجبات أو النتائج أو إعدادات Supabase.
- لم تُنشأ صفحات لسجل النشاط أو الإعدادات، لأن تأمين البيانات وتوفير واجهات خادمية حقيقية لم يكتمل.
- لم يُنشأ نظام جديد لتصحيح الواجبات داخل المنصة.
- **أزرار الإنشاء والتعديل تعتمد على وظائف Supabase الموجودة في المشروع؛ لم تختبر بحسابات الإنتاج.**

## مخاطر قائمة

**التمرير في الواجهة لا يثبت سلامة الصلاحيات في قاعدة البيانات.** إدارات الحسابات وتغيير أدوار الملفات وفتح المحتوى وخطر `iframe` غير المعزول جميعها تعتمد على مراجعة Supabase وتطوير آلية HTML الآمنة. لا يجوز اعتبار إخفاء رابط أو خيار إداري إصلاحًا أمنيًا على مستوى الخادم.

## الخطوة التالية

استكمال تصميم المواد والمناهج أو بناء عقد ملفات HTML الآمن؛ كلاهما يتطلب عدم تغيير قاعدة بيانات الإنتاج قبل اتصال مشروع Supabase الصحيح وإنشاء نسخة احتياطية. يمكن مواصلة التوثيق والنماذج المعزولة دون قاعدة بيانات.
